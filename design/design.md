# claude-code-hikitsugi — 設計（公開版）

## 課題

Claude Code の長いチャットは、自動要約（コンパクション）で記憶の細部を失う。
研究で「圧縮時に一貫して失われる」と実証されているのは次の5種：
数値の精度／ハード制約／決定の理由／ターン間の依存関係／暗黙の好み。

一方、生ログ（`~/.claude/projects/**/*.jsonl`）は無傷で全部残っている。
問題はサイズ（1か月のチャットで40MB超＝コンテキスト上限の10倍以上）で、直接は読めないこと。

## 解法：二方向アプローチ

1. **押し出し**：生ログを機械抽出して凝縮メモ（handoff.md／digest.md）を作り、新チャットに読ませる
2. **引き出し**：メモに生ログのパスとgrep例を載せ、新チャットが細部を自力で検索できる導線を残す

メモだけでは細部が無い。生ログだけでは大きすぎる。両方で1セット。

## 構成（2階建て）

| 層 | 実体 | 役割 |
|---|---|---|
| スキル | skill/SKILL.md | 「◯◯を継いで」の一言を受けて、特定→生成→読込→引き継ぎ宣言を行う手順書 |
| エンジン | skill/hikitsugi.py | .jsonlをストリーミング解析し、メモ2枚を生成（標準ライブラリのみ・通信なし） |

7章の引き継ぎ整理（目標・決定・未完了・つまずき・保留・辞書・不明点）は、
エンジンが機械抽出した材料をもとに**新チャットのAIが行う**。エンジンは材料と指示を供給する。

## 設計上の決定と理由

| 決定 | 理由 |
|---|---|
| マスキングは抽出の境界で、切り詰めより先に適用 | 切断面をまたぐ秘密がパターン照合を逃れて漏れるのを防ぐ |
| AI側の発言もダイジェストに収録 | 「決定の理由」は人間ではなくAIの返答に書かれることが多い |
| system系ブロックは項目単位で除外 | 本文と同居するメッセージで本文を失わないため |
| 未知type・非辞書JSONは黙って読み飛ばす | ログ形式は公式に「バージョンで変わり得る」とされているため |
| タイムスタンプはローカル時刻へ変換 | ログはUTC記録。日付見出しと --since の判定が実感とずれるのを防ぐ |
| サブエージェント会話は対象外（明記） | 別ファイル群に保存されており、主会話の物語を優先するMVP判断 |
| 完全ローカル・通信なし | 会話ログは最高機密級の個人データであるため |

## 品質保証

`eval/oracle.py --selftest` が外部オラクルとして24項目を機械判定する
（秘密の漏れ・切断面漏れ・壊れた入力への耐性・抽出の正しさ・引数検証）。

## 既知の限界

- マスキングは既知パターンのみ。共有前の目視確認は代替できない
- 機械抽出は意味の分類（決定か雑談か）をしない。意味づけは読み手のAIに委ねる
- サブエージェントのログは含まれない
