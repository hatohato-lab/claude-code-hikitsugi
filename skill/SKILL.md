# hikitsugi — 前のチャットを引き継ぐ

ユーザーが「◯◯を継いで」のようにチャット名を指定したら、次の手順を実行する。

## 手順

1. **候補を探す**（このSKILL.mdと同じフォルダに hikitsugi.py がある）

   ```
   python "<このスキルのフォルダ>/hikitsugi.py" --find "◯◯"
   ```

   - 候補が1件 → そのまま手順2へ
   - 候補が複数 → 一覧をユーザーに見せて選んでもらう
   - 候補が0件 → `--list` の結果を見せて、どれか尋ねる

2. **引き継ぎメモを生成する**

   ```
   python "<このスキルのフォルダ>/hikitsugi.py" --session <セッションID8桁>
   ```

   出力先が表示される（既定: `~/.claude/hikitsugi-out/<セッション>/`）。

3. **handoff.md を読む**。足りなければ digest.md も読む（大きい場合は末尾＝直近から）。

4. **引き継ぎ宣言をする。** 次の7点に整理してユーザーに示す。

   ①このチャットの目標 ②決まったこと（理由つき） ③未完了タスクと次の一手
   ④つまずき履歴 ⑤保留中の判断 ⑥固有名詞の辞書 ⑦読み取れなかった不明点

5. 以後の作業で細部が必要になったら、handoff.md 記載の**生ログをgrepで検索**する。
   生ログ全体は巨大なので**絶対に全部読まない**。

## 短い引き継ぎ（--brief・2026-09-12 追加）

`--session` に `--brief` を足すと、handoff.md / digest.md に加えて **brief.md**（5種だけ・3000字目安）と、
新しいチャットに貼るだけで引っ越せる **3行** を出す。

```
python "<このスキルのフォルダ>/hikitsugi.py" --session <セッションID8桁> --brief --out "<置き場>"
```

出力される3行（これを新しいチャットに貼る）
```
【引き継ぎ】これを新しいチャットに貼ってください
前のチャット: <名前>（ID <8桁>）
メモ: <brief.md の絶対パス>
```

brief.md の5種：決まったこと／いまの作業と止まっている場所／残作業と順番／成果物のパス／直近の指示と注意点。
`--brief` は**通信なしのローカル抽出**で書く（2026-09-20 変更。以前は自動で `claude -p` を呼んでいた）。

AI に要約させたいときだけ `--ai-brief` を足す。これは**通信あり**で、会話から作った材料を
`claude -p`（道具なし・MCPなし・設定なし）へ第三者として読ませ、利用枠を消費する。
AIが使えなかったときは言葉の一致で抜き出し、末尾に「質は低い」と明記する。

新しいチャット側：貼られた3行を見たら、メモのパスを読んで続きから始める（名前もIDも人が調べない）。

## 見張り（watch.py・2026-09-12 追加）

古いチャット側で「そろそろ引き継いでください」を自動で出す仕組み。発言のたびに自分の生ログを測り、
圧縮1回以上 または 15MB超 のときだけ案内を1回出す（同じ状態では繰り返さない）。基準に届かなければ無音。

登録は ~/.claude/settings.json の hooks.UserPromptSubmit に次の1本を足す（人が手で行う）。
```
{"hooks": [{"type": "command", "command": "python -X utf8 \"<このスキルのフォルダ>/watch.py\"", "timeout": 15}]}
```

案内が出たら AI は次を行う：本人に1行伝える → `--brief` でメモを作る → 出た3行をコードブロックで表示し「新しいチャットを開いてこれを貼ってください」と伝える。
止め方：settings.json からその1本を消す。

## 守ること

- `[MASKED:...]` は秘密情報の跡。**復元も推測もしない**。ユーザーに聞く
- 引き継ぎメモに書かれていないことを、前のチャットで「決まった」と思い込まない（⑦不明点として正直に言う）
- handoff.md / digest.md は共有前にユーザーの目視確認が必要と伝える
