claude-code-hikitsugi v3 の詳細解説

2026-09-20 作成　／　v3.0.0　／　hatohato-lab

前のセッションを引き継ぐプラグイン。 Claude Code が圧縮のたびに生ログへ書く要約を、そのまま新しいセッションに読ませる。 自分で要約は作らない。

しくみ圧縮のたびに書かれる要約を、次のセッションが読む

Claude Code は会話が文脈ウィンドウを埋めると、それまでの内容を要約して詰める（コンパクション）。 そのとき要約の全文が、そのセッションの生ログ（~/.claude/projects/<プロジェクト>/<ID>.jsonl）に1行で残る。 目印は "isCompactSummary":true。

要約は9つの見出しで固定されている。

1  Primary Request and Intent     もともとの依頼と意図
2  Key Technical Concepts         使った技術の要点
3  Files and Code Sections        触ったファイルとコード
4  Errors and fixes               失敗と直し方
5  Problem Solving                解決したこと
6  All user messages              使う人の発言の全文
7  Pending Tasks                  残っている作業
8  Current Work                   いま何をしていたか
9  Optional Next Step             次の一手

2026-09-20 に124セッション・787MBの生ログを全件調べたところ、19本すべてがこの形だった。平均15,375字。

last_summary.py がやること

  1. ~/.claude/projects/ の下の .jsonl を見て、名前かIDの先頭で1本に絞る。パスを直接渡してもよい
  2. その1本を先頭から読み、"isCompactSummary":true を含む行を探す。壊れた行は飛ばす
  3. 最後に見つかった1行の message.content を本文として取る。compact_boundary の行数を圧縮回数として数える
  4. 要約が無ければ「要約がありません。前のセッションで /compact を打ってから」と出して終了コード2
  5. あれば、ログのパス・圧縮回数・要約の時刻・本文を出す。時刻には「この時刻より後の会話は入っていない」と添える

ログの大きさを基準から外した理由は、大きさと文脈の重さが一致しないから。 実測では25MBで圧縮0回のセッションがある一方、40MBで1回だけのものもあった。 道具の実行結果は生ログに丸ごと残るが、文脈には残らないため。

制限できないこと

できないことどうするか
圧縮されたことのないセッションを引き継ぐ古いセッションで /compact を1回打つ
要約の時刻より後の会話を含める引き継ぐ直前に /compact を打つ
サブエージェントの会話を含める同名フォルダーの生ログを別に読む
生ログの形式が変わったとき「要約がありません」と正直に出す。目印のキーを直す
